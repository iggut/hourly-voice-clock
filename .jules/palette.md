## 2024-03-24 - Do not blindly add ARIA/Content descriptions to adjacent decorative icons
**Learning:** Adding content descriptions to icons that are directly adjacent to text elements describing the same action introduces redundant screen reader announcements (e.g., "Special voices. Special voices."), worsening the accessibility experience. `contentDescription = null` is often intentionally used for these decorative icons.
**Action:** When auditing missing content descriptions, always check the surrounding layout context (e.g., `Row` or `Button`). Only add descriptions to true icon-only interactive elements or standalone informational icons.
## 2024-03-24 - Grouping toggleable row content for screen readers
**Learning:** When using `Modifier.toggleable` on a layout container like a `Row` to create a large touch target (e.g., for settings switches), screen readers like TalkBack often read the row's text and the switch state as two separate, disjointed elements. This leads to a poor accessibility experience where the user has to swipe multiple times to understand a single setting.
**Action:** Always apply `.semantics(mergeDescendants = true) {}` (and ensure `androidx.compose.ui.semantics.semantics` is imported) to the parent modifier chain before applying interactive modifiers like `toggleable` or `selectable`. This forces the screen reader to group the nested text and the switch state, announcing them together as a cohesive interactive element.
